# Передача проекта команде

Актуальная ветка: **demoVer-1**. Этот документ описывает продукт после доработок ассистента и заявок. Исторические отчёты шагов 1–2 не являются описанием текущей конфигурации.

## 1. Что уже готово

- FastAPI + адаптивный интерфейс «событие.», запуск без Node/GPU.
- 70 профилей: 66 исходных, 4 дополнения команды; 17 синтетических помечены.
- Строгие фильтры, настоящие замороженные E5-эмбеддинги, стабильный топ-3, объяснения и исходные цитаты.
- При пустом/неполном результате — проверенные изменения одного условия. Пользователь применяет их сам.
- Сравнение дат, редкие/пустые категории, диагностическая статистика.
- LLM-композиция по фактам; основная выбранная модель **OpenAI GPT-6 Sol**, шаблон при недоступности API.
- Обращение команде: условия события, контакт, согласие, SQLite, приватная квитанция, защита от повторов. Основной выбранный канал — **email**; SMTP-адаптер готов. Telegram остаётся необязательной альтернативой.

**Не объявляйте реальное подключение завершённым:** живой GPT-6 Sol, почтовая отправка и Docker пока не проверены. Без секретов сайт полностью показывает подбор, но использует шаблон объяснения; форма отправки отключена. Синтетические профили принимают только просмотр/скачивание примера.

## 2. Получить и запустить

```bash
git clone --branch demoVer-1 https://github.com/BAITC-Hacks/hack-89a1ad55-the-good-the-bad-and-the-ugly.git
cd hack-89a1ad55-the-good-the-bad-and-the-ugly
```

В Windows откройте `start-demo.cmd`. Он найдёт Python 3.12+, создаст окружение и откроет `http://127.0.0.1:8000`. Окно сервера должно оставаться открытым; остановка — `Ctrl+C`. Первый запуск требует сети для зависимостей, поэтому «60 секунд на любом чистом ПК» не подтверждено. Проверка без запуска: `start-demo.cmd --check --no-browser`.

Linux/macOS или ручной запуск:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m uvicorn contractor_matching.api:app --app-dir app --host 127.0.0.1 --port 8000 --no-access-log
```

В Windows для тех же команд используйте `.venv\Scripts\python.exe`. На исходной машине launcher также умеет использовать уже подготовленное окружение вне репозитория; на машине команды создайте собственное `.venv` приведёнными командами. `127.0.0.1` работает только на машине сервера. Для публичной ссылки нужен отдельный хостинг; GitHub Pages не запускает FastAPI.

## 3. Подключить GPT-6 Sol

Скопируйте `.env.example` в `.env` **если `.env` ещё нет**, не затирайте существующие секреты. Старый опубликованный ключ отозвать. Новый ключ вводится только локально:

```dotenv
ASTRA_API_PROTOCOL=openai-chat-completions
ASTRA_CHAT_COMPLETIONS_URL=https://api.openai.com/v1/chat/completions
ASTRA_MODEL=gpt-6-sol
ASTRA_API_KEY_1=<новый ключ OpenAI>
```

`ASTRA_*` — историческое имя переменных основного провайдера. Фактически код определяет GPT-6 Sol как `openai`; UI не должен называть его Astra. Ключу нужен доступ к этой модели и рабочий API-баланс. Приоритет Sol заменяет прежнее пожелание Astra по последнему решению пользователя. Параметры Sol: `reasoning_effort=none`, `temperature=0`, лимит 1000 токенов. [Официальный контракт](https://developers.openai.com/api/docs/models/gpt-6-sol).

Перезапустите сервер. Проверьте `/api/meta`: `runtime.explanation_model=gpt-6-sol`, режим `openai_then_template`. Выполните ещё не кешированный запрос и в ответе `/api/search` проверьте **`cards[*].explanation_source=openai`**. HTTP 200 и настроенный режим сами по себе не доказывают живую генерацию: с таймаутом/ошибкой используется `template`. Принятый шаблон тоже сохраняется для повторяемости; для отдельной живой проверки можно временно задать новый `CACHE_PATH=.cache/live-check.sqlite3`, не удаляя прежний кеш.

Основной провайдер имеет общий предел попыток 2.5 с, резервный 1.5 с, весь поиск 8 с. Если живая модель не укладывается, измерьте latency и обсудите изменение бюджета времени; не скрывайте постоянный fallback под названием «LLM работает».

## 4. Подключить email заявок

Получатель команды согласован в рабочей переписке. В локальном `.env` исходной машины он уже записан; этот файл в Git/ZIP **не входит**. На машине тиммейта нужно указать подтверждённый адрес команды в `INQUIRY_EMAIL_TO`. Отправителем может быть отдельный сервисный ящик.

```dotenv
INQUIRY_TRANSPORT=smtp
SMTP_HOST=smtp.gmail.com
SMTP_PORT=465
SMTP_USERNAME=<почта отправителя>
SMTP_PASSWORD=<пароль приложения, только локально>
SMTP_FROM=<подтверждённая почта отправителя>
INQUIRY_EMAIL_TO=<почта команды>
INQUIRY_DB_PATH=.cache/inquiries.sqlite3
```

Для Gmail используется пароль приложения при включённой двухэтапной аутентификации; обычный пароль Google не подходит. Возможность паролей приложений зависит от настроек аккаунта. Если она недоступна, используйте согласованный почтовый сервис/OAuth и соответствующий адаптер. [Инструкция Google](https://support.google.com/accounts/answer/185833). Пока секреты не готовы, оставьте `INQUIRY_TRANSPORT=` пустым: сайт запустится без отправки. Частично включённая конфигурация специально блокирует старт с безопасной ошибкой.

SMTP работает только с проверенным TLS: 465 или STARTTLS на 587. После перезапуска `/api/meta` покажет `inquiries.enabled=true`; это означает заполненную конфигурацию, не успешный тест доставки. Отправьте через UI **одну явно обозначенную тестовую заявку** с несинтетическим профилем и собственным тестовым контактом, затем проверьте её получение в почте команды. Отдельно проверьте неверные SMTP-настройки: UI должен показать ошибку или неизвестный статус, а не обещать бронь.

Статус `delivered_to_team` означает принятие сообщения настроенным каналом (для SMTP — почтовым сервером), не попадание во «Входящие», прочтение или подтверждение заказа. `delivery_unknown` после таймаута автоматически не повторяется: сообщение могло уйти. Повтор с тем же содержимым возвращает ту же заявку; не «исправляйте» это принудительной повторной отправкой.

Контакты хранятся в SQLite вне static; в LLM они не передаются. Публичного списка заявок нет. Квитанция требует opaque ID и Bearer token; токен нельзя передавать в URL/логи. Реальных контактов исполнителей в датасете нет: сотрудник должен установить соответствие с настоящим подрядчиком вручную. Для полноценного marketplace нужен отдельный настоящий каталог.

## 5. Проверка перед презентацией

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
docker compose config
docker compose up --build -d
```

Используйте Python из окружения проекта. На Windows при проблемах с правами временной папки: `python -m pytest -q -p no:cacheprovider --basetemp .test-tmp-run`. Не выбирайте каталог с ценными файлами: pytest очищает свой basetemp. Автотесты отключают реальные API и отправку.

Показать: ведущие Алматы → сравнение 4/5 октября → редкие флористы → «все вне бюджета» → применить предложенный бюджет → раскрыть цитату → открыть обращение → синтетические декораторы с запретом реальной заявки. Подробно: [docs/demo-script.md](docs/demo-script.md). На живой конфигурации отдельно проверить источник LLM, скорость и получение тестового email.

## 6. Commit / PR / merge

Все доработки вести в `demoVer-1`. Перед коммитом проверить `git status`, тесты и staged diff; `.env`, ключи, SQLite, кеши и venv не добавлять. Убедиться, что remote branch не ушла вперёд.

```bash
git switch demoVer-1
git pull --ff-only origin demoVer-1
git add <только проверенные файлы>
git commit -m "Describe the completed change"
git push origin demoVer-1
git fetch origin
git merge-base origin/main origin/demoVer-1
```

При последней проверке `main` был отдельным корневым коммитом `890505950b64010585a73a63b0ebadcd1f287e9d`, без общего предка с demo. Это состояние нужно **проверить заново**. Если истории всё ещё не связаны:

```bash
git switch -c release/demoVer-1 origin/main
git merge --no-ff --allow-unrelated-histories origin/demoVer-1
```

Разрешить конфликт README в пользу текущей документации продукта, сохранить остальные осмысленные изменения. После разрешения конфликта `git add <файлы>` и `git commit`, снова тесты, `git push -u origin release/demoVer-1`. Открыть PR **release/demoVer-1 → main**, проверить diff и CI, затем обычный merge. Если общий предок уже есть — можно PR demoVer-1 → main. Не использовать force push, сброс чужой ветки или скрипт, стирающий `main`.

GitHub Actions ранее завершался **до запуска шагов**, логи отсутствовали. Если повторяется, владельцу репозитория открыть Actions и прочитать точную annotation/ошибку запуска. Не списывать это на приложение, биллинг или квоты без текста ошибки. Docker в исходной среде отсутствовал: CI/контейнерный тест остаётся обязанностью принимающей команды.

## 7. Что обязательно, а что дополнение

PDF требует рекомендацию внутри каталога, ≤3 варианта, конкретные объяснения, повторяемость, честные пустые результаты и демо с занятостью. Аккаунты, движок БД, checkout, оплата и обязательный merge в PDF не заданы. Заявки/уведомления — расширение по дополнительному запросу пользователя. Без регистрации можно искать и оставить обращение; реальные кабинеты/оплата/бронь требуют нового объёма и данных. [Полная сверка](docs/readiness.md).
