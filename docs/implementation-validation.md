# Проверка реализации · 23 сентября 2026

Среда: Windows, Python 3.12.14, локальный Uvicorn на 127.0.0.1:8000. Режим `frozen_semantic` + `template`. Настоящие E5-эмбеддинги рассчитаны заранее; внешние LLM в этом прогоне не использовались.

## Автоматические проверки

Итоговый полный pytest после доработок: **312 тестов прошли**. После уточнения текста квитанции дополнительно прошли 61 тест ядра/API заявок. `pip check` не нашёл конфликтов зависимостей, `node --check app/static/app.js` прошёл. Есть предупреждение Starlette о будущей замене транспорта TestClient; ошибки и упавшие проверки отсутствуют.

Добавленные проверки: 19 сценариев советов ассистента, 42 теста хранения/доставки заявок, 19 интеграционных API-проверок, 48 моков SMTP/Telegram и16 проверок конфигурации. Проверяются consent, запрет синтетических заказов, фильтры перед записью/отправкой, идемпотентность, неопределённый исход доставки без повтора, приватность квитанции, сокрытие PII (включая неизвестные JSON-ключи), Origin, лимит фактического тела запроса и частоты. Автотесты изолируют реальные секреты `.env` и внешние провайдеры.

LLM: проверены ограниченная композиция вместо выбора готового ответа, смысловые группы фактов, подмена факта, отрицания и добавленные услуги, таймауты/fallback, перезапуск кеша и20 повторов. Запрос к OpenAI GPT-6 Sol проверен моками: `reasoning_effort=none`, `temperature=0`, `max_completion_tokens=1000`; происхождение ответа `openai`.

Покрытие поведения: строгий парсинг, календарь, бюджет/формат/длительность/язык, первая причина, зарубежный каталог, None-длительность, формула/tie-break, 20 повторов, устаревшие векторы и факты, bounded LLM output, таймауты, ключи, конкуренция и перезапуск кеша. Дополнительно проверены 100 валидных комбинированных запросов и все возможные тройки профилей внутри города/категории на различимость фактов.

В первом прогоне базовой версии отдельно отправлено **140 HTTP-запросов**: каждый из семи сценариев повторён20 раз. Следующая таблица сохраняет измерения этого исходного прогона до добавления заявок и новых объяснений; это локальный HTTP round-trip, не обещание скорости внешнего API.

Это измерение локальной машины без внешнего LLM. `start-demo.cmd --check --no-browser` успешно распознал работающий экземпляр и напомнил о перезапуске после изменения `.env`.

## Проверка интерфейса

Проверено в браузере на работающем API: стартовая тройка, сравнение 4/5 октября, декораторы Астаны, отсутствие категории за рубежом, читаемая мобильная компоновка при ширине 390px. На двух датах ведущие меняются с Софи Хаттер/Джинбей/Кики на Софи Хаттер/Хаул/Буллма. API подтверждает busy для пропавших кандидатов; UI показывает эту причину.

JavaScript проходит `node --check`; внешних скриптов, шрифтов и CDN нет. Фронтенд выводит данные через `textContent`. API не показывает тела ошибок провайдеров/ключи. Compose YAML разобран локально.

После доработок в браузере проверены: пустой поиск флористов при100000₸ → предложение200000₸ → одна карточка и следующий проверенный бюджет; раскрытие дословной цитаты; окно обращения без настроенного канала, без сбора контактов; мобильная вёрстка при390px. На отдельном localhost-сервере с фиктивным транспортом проверены заполнение формы, согласие, сохранение, приватная квитанция и блокировка повторного submit. **Внешнее письмо при этом не отправлялось.**

## Границы проверки

- Выбран OpenAI **GPT-6 Sol**, официальный контракт проверен. Живой вызов не выполнен: опубликованный в переписке ключ не использовался; требуется новый локальный ключ и доступ к модели. Настройка адаптера и резервирование проверены моками; UI честно показывает шаблон, когда он использован.
- Email выбран, SMTP-код готов, но живой доступ отправителя и получение письма не проверены. SMTP acceptance не означает доставку во «Входящие», прочтение или бронь. Локальный `.env` отсутствует в Git/архиве.
- Docker отсутствует в локальном окружении. Dockerfile, Compose и проверка сборки/healthcheck включены в CI; локальная контейнерная сборка не заявляется.
- Эти проверки подтверждают корректность правил и воспроизводимость. Они не доказывают качество подрядчиков, актуальность календаря вне датасета или оптимальность весов на реальных пользовательских выборах.
