# Запуск сайта и подключение API

## Windows: открыть одним файлом

Распакуйте проект в отдельную папку или клонируйте ветку `demoVer-1`. Дважды нажмите **`start-demo.cmd`**. Откроется терминал, после готовности сервера — браузер с **http://127.0.0.1:8000**. Пока сайт нужен, оставьте терминал открытым. Для остановки нажмите `Ctrl+C` в этом терминале.

Скрипт использует готовую `.venv`, а в исходной папке разработки может использовать уже подготовленное окружение из `../../work/product-venv`. На другом компьютере он ищет Python 3.12 через `py`, затем Python 3.12+ из PATH. На компьютере с Codex также может использоваться его установленный Python. Если Python не найден, установите Python 3.12+ с python.org и включите **Add Python to PATH** при установке.

При первом запуске создаётся локальная папка `.venv` и устанавливаются зафиксированные зависимости. Для этой подготовки нужен интернет; она может занять несколько минут. Повторный запуск с готовыми зависимостями не загружает модель и не устанавливает пакеты. Заявление «до 60 секунд» относится к подготовленному окружению, а не к первой загрузке Python, Docker или зависимостей.

Запуск из PowerShell без изменения ExecutionPolicy:

```powershell
.\start-demo.cmd
```

Если порт занят другим приложением:

```powershell
.\start-demo.cmd --port 8001
```

Если уже работает HackAlem, повторный запуск откроет готовый сайт и не станет создавать второй сервер. **После изменения `.env` или исходников нужно остановить прежний сервер и запустить заново** — повторное открытие сайта не применяет настройки к уже работающему процессу.

Проверка без запуска и без установки:

```powershell
.\start-demo.cmd --check --no-browser
```

## macOS / Linux или ручной запуск

Из корня проекта, используя Python 3.12+:

```bash
python3 scripts/run_demo.py
```

Скрипт создаст `.venv` при необходимости. Чтобы браузер не открывался автоматически, добавьте `--no-browser`. Сам сервер слушает только `127.0.0.1`: это сайт на вашем компьютере. Этот адрес нельзя отправить жюри как публичную ссылку. Для удалённой демонстрации потребуется отдельный сервер с HTTPS и настройками хранения заявок; текущий локальный запуск ничего не публикует.

## API без отправки ключа в переписку

1. Скопируйте `.env.example` в `.env` в **корне проекта**.
2. В обычном текстовом редакторе впишите ключ и подтверждённые провайдером URL и model ID.
3. Остановите и заново запустите сервер.

```dotenv
ASTRA_API_PROTOCOL=openai-chat-completions
ASTRA_CHAT_COMPLETIONS_URL=https://api.openai.com/v1/chat/completions
ASTRA_MODEL=gpt-6-sol
ASTRA_API_KEY_1=your-key
```

По последнему решению команды основной провайдер — OpenAI GPT-6 Sol; `ASTRA_*` осталось историческим префиксом переменных. URL и model ID сверены с официальной документацией. Доступ аккаунта и живую генерацию нужно проверить отдельно: в карточке должен быть `explanation_source=openai`. Без ключа сервис работает с локальными эмбеддингами и объяснениями по проверенным фактам. Подробная передача команде — в `HANDOFF.md`.

`.env` исключён из Git. **Не добавляйте его принудительно (`git add -f`) и не вставляйте ключ во фронтенд.** В интерфейсе ключ не показывается. Чтобы согласовать интеграцию, достаточно названия провайдера, ссылки на его документацию и точного model ID; сам ключ лучше записать локально.

Окружение процесса имеет приоритет над `.env`, включая явно пустые значения. Файл читается только из корня проекта. Поддерживаются переменные Astra и резервного LLM из `.env.example`, а также `DATA_DIR`, `CACHE_PATH` и `INQUIRY_DB_PATH`; относительные пути разрешаются от корня проекта. `NVIDIA_API_KEY` зарезервирован из старого примера и не включает внешние эмбеддинги.

Формат строгий: `KEY=value`, пустые строки, комментарии `#`, значения в одиночных или двойных кавычках. `$VAR`, обратные кавычки и `$(...)` остаются обычным текстом и не выполняются. В кавычках `#` — часть значения; без кавычек пробел перед `#` начинает комментарий. Переносы внутри значения, повторные или неизвестные ключи и строки `export ...` не поддерживаются. При ошибке сообщается только номер строки, без её содержимого.

## Канал получения заявок

Заявка на услуги и подтверждённое бронирование — разные этапы. В каталоге нет подтверждённых контактов подрядчиков. Канал доставки заявки нужно выбрать и настроить отдельно; одна запись в SQLite не означает, что подрядчик получил сообщение или согласился на заказ.

Для выбранного владельцем проекта канала **email** нужны настройки SMTP почтового провайдера и адрес получателя команды. Впишите их **только в локальный `.env`**:

```dotenv
INQUIRY_TRANSPORT=smtp
SMTP_HOST=smtp-host-from-your-provider
SMTP_PORT=465
SMTP_USERNAME=account-from-your-provider
SMTP_PASSWORD=app-password-or-smtp-credential
SMTP_FROM=sender@example.com
INQUIRY_EMAIL_TO=team@example.com
```

Это обозначения полей, а не действующая конфигурация. Для порта **465** используется TLS с начала соединения; для **587** — обязательный STARTTLS. Другие порты и незашифрованная отправка не поддерживаются. Сертификат сервера проверяется. Некоторые провайдеры требуют отдельный пароль приложения или SMTP-ключ: используйте инструкцию именно вашего провайдера. Контакт посетителя попадает только в текст письма и не может изменить адрес получателя.

Содержимое `.env` не нужно копировать в чат или включать в скриншоты. Для настройки достаточно сообщить выбранного почтового провайдера, публичную ссылку на его инструкцию SMTP и адрес команды; пароль внесите локально. Путь базы заявок задаётся `INQUIRY_DB_PATH`.

Успешный статус SMTP означает, что почтовый сервер принял сообщение. Он не подтверждает прочтение письма, согласие подрядчика или бронирование. При таймауте результат может быть неизвестен; автоматической повторной отправки нет, чтобы не создать дубль. После согласованного теста проверьте папки «Входящие» и «Спам» на стороне команды.

В коде также подготовлен отдельный необязательный Telegram-адаптер (`INQUIRY_TRANSPORT=telegram`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`). При выбранном email он не используется.

Пока канал и получатель не согласованы, оставьте параметры доставки незаполненными. Поддержка переменных сама по себе не подтверждает доставку: после настройки адаптера нужен отдельный согласованный проверочный запрос и проверка статуса отправки. Автоматической отправки тестового сообщения при чтении `.env` или запуске скрипта нет. После изменения настроек перезапустите сервер.

## Docker

При установленном Docker Compose из корня проекта:

```bash
docker compose up --build -d
docker compose logs web
```

Адрес: http://localhost:8000. Остановка: `docker compose down`. После правки `.env`: `docker compose up -d --force-recreate`. Первая сборка требует сети; обычный подбор после неё использует сохранённые векторы. В этой среде Docker не установлен, поэтому локальная проверка контейнера остаётся отдельным пунктом проверки перед сдачей.
